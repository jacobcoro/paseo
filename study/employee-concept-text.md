## Root-owned pending creation

Supply an exact instance target and workspace, approved model/thinking/mode,
requested UUID, nonce, idempotency key, constructor digest and eight source/config
pins. The constructor supplies only `providerOptions: {textOnly: true}`. No initial
prompt enters creation. Actor text enters later through guarded submission.

The host requires `authorize`, `assertPrecreation` and `observeOwner` readers.
Authorization binds the exact intent and Root receipt. Precreation evidence binds
the current reviewed source/config closure. The actual owner reader supplies
visibility, stored seal, workspace and all nine observed identity/generation
fields. Public snapshots lack the stored seal and explicit visibility. Intended
IDs, titles, file modes, hashes and acknowledgements cannot fill these gaps.

Creation fsyncs an inactive intent under an exclusive cross-process owner before
SDK access. The managed modern creation API receives the requested ID and key.
Legacy hosts, collisions, ambiguity, identity drift and deadlines retain the
intent and owner lease. No retry, stale steal, archive or foreign cleanup occurs.
Late acceptance cannot undo withdrawal. Repeated withdrawal preserves its epoch
and nonce and remains available after creation authorization expires or revokes.

`admitInactive` requires the separate `verifyAdmission` reader's Root receipt,
actual nine fields, current exact source pins and independent zero-tool checks.
It writes only an inactive control record. Root must separately approve actual
adoption, host custody and any active actor assignment. No source API here grants

`employee-concept-resume.mjs` is Root-only. Generic `resumeAgent(handle)` can create
a new managed ID, so this seam uses the existing exact-ID `refreshAgent` API.
Refresh may restore a workspace or interrupt a turn. Its independent preflight

live tuple under the submission lease. Missing preflight denies; this source does
not implement that reader or prove the daemon cannot race another entrypoint.

never a kernel quiescence claim. The Hermes caller still needs an independent

worker-writable roots. A private directory alone is not filesystem isolation.

profile. Root's independent readers must prove loaded source/SDK/CLI/plugin/config
